# Sentinel: поэтапный поток

## Старт сессии
1. `repo-scout` (haiku): прочитать `HANDOFF.md` — ветка, статус этапов, следующие шаги.
2. Базовая проверка: `bash scripts/setup-linux.sh`, затем `dotnet build` и `dotnet test`. Красное до начала работы — сначала зафиксировать в HANDOFF.md.

## Итерация (один модуль)
1. Реализация — `code-implementer` (sonnet) по короткому ТЗ: модуль, интерфейсы, критерии приёмки.
2. Сборка + тесты. Коммит в стиле `Stage N (k/m): <модуль>`; push в рабочую ветку.
3. Обновить `HANDOFF.md` (через `repo-scout`): что сделано, что не проверено, следующий модуль.
4. Контекст > 150k токенов или 3 неудачные итерации CI → остановиться и предложить новую сессию.

## Формулировки
Sentinel — защитный инструмент обнаружения и устранения угроз на собственном компьютере. В задачах и коммитах
использовать точные нейтральные термины: аудитор (auditor), проверка целостности (integrity check), правило обнаружения,
карантин (quarantine), манифест отката (rollback manifest), список исключений (allow-list), отчёт.
Тестовые данные — только синтетические (строка EICAR, самосозданные образцы). Не описывать и не реализовывать обход чужих средств защиты.

## Тесты: два контура
- Linux (xUnit, `dotnet test`): парсеры, правила, хеширование, отчёты, логика карантина на временных каталогах, фейки системных API.
- Windows-only (атрибут `WindowsFact`, пропускаются на Linux): `WinVerifyTrust`, реестр, службы, Defender, запуск WPF.
  Компиляция Windows-проектов на Linux: `-p:EnableWindowsTargeting=true`; запуск — только на Windows.
Каждый Windows-only тест и непроверенный участок — в раздел «Не проверено / нужна проверка на Windows» файла `HANDOFF.md`.

## Отчёт (≤6 строк)
Сделано / Проверка (build + число тестов, пропущено) / Артефакт (коммит) / Следующий шаг.
