# Правила разработки антивирусного движка

1. **Никаких заглушек и симуляций:** Запрещено писать `// TODO`, `pass`, пустые обработчики или проверку только по имени файла. Каждый детектор обязан использовать реальные системные механизмы Windows (Win32 API, WMI, чтение PE-заголовков, анализ энтропии, проверку цифровых подписей WinVerifyTrust, YARA-правила).
2. **Безопасность операций (Карантин вместо слепого удаления):**
   - Перед удалением угрозы процесс и его дочерние процессы корректно завершаются (`TerminateProcess` / дерево процессов).
   - Файл не стирается безвозвратно сразу, а перемещается в изолированный карантин с XOR-шифрованием заголовка (чтобы он не мог запуститься) и записью метаданных в `quarantine_manifest.json` для возможности отката.
   - Критические системные файлы Windows (`System32`, подписанные драйверы Microsoft) защищены белым списком (Whitelist) по проверке валидной цифровой подписи.
3. **Протокол экономии токенов и самопроверки:**
   - Работай строго по одному модулю за итерацию. Не переписывай весь проект целиком — вноси точечные правки.
   - После написания кода **обязательно** выполни сборку и прогон тестов в терминале (`dotnet build` / `dotnet test` или `cargo test`) в рамках этой же сессии.
   - Тестирование детекта и чистки проводи только на безопасных синтетических артефактах (тестовая строка EICAR, тестовые ключи реестра в `HKCU\Software\TestAV`, пустые PE-заглушки с высокой энтропией).
   - Если компилятор или тест выдал ошибку — исправь её самостоятельно до того, как отвечать пользователю.

# Правила 1.1.0 (обязательны)

4. **Никаких заглушек в продакшене:** запрещены имитация загрузки баз, пустые обработчики кнопок, захардкоженные массивы из нескольких хешей. Загрузчики, парсеры, IPC-команды и кнопки UI должны работать по-настоящему; всё, что нельзя проверить в среде, честно записывается в `HANDOFF.md`.
5. **Потоковый ввод-вывод:** запрещены `File.ReadAllBytes`/`ReadAllText` для сканируемых файлов. Хеш SHA-256 (`IncrementalHash`) и энтропия Шеннона считаются потоком буфером 64 КБ; в память целиком читается только ограниченное окно для сигнатурного поиска.
6. **Защита от петель NTFS:** при обходе каталогов пропускать `FileAttributes.ReparsePoint` (junction и symlink: `All Users`, `Application Data`, `Local Settings`).
7. **Неприкосновенность ядра ОС и самозащита:** не изолировать и не завершать `csrss.exe`, `smss.exe`, `lsass.exe`, `wininit.exe`, `services.exe`, `explorer.exe`, `ntoskrnl.exe`, `winload.efi` и каталоги `C:\Program Files\Sentinel`, `C:\ProgramData\Sentinel`.
8. **Скоринг, а не одно правило:** вердикт складывается из `ThreatScoringEngine` (0–100). Высокая энтропия .NET-сборки не является признаком упаковщика; подпись Microsoft (встроенная или каталожная) в защищённом каталоге даёт `Clean`.
9. **Телеметрия Microsoft в `hosts`** — `Info`, никогда не удаляется автоматически; блокировка доменов обновлений и защиты — только решение пользователя; перенаправление на внешний адрес — `Critical`.
