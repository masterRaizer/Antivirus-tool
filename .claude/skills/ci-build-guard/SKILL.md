# CI build guard

## Цикл
1. Запушить коммит (обычный commit + push; не force).
2. Проверку делегировать `ci-poller` (haiku): «run для <sha>, workflow <имя>». Сам логи не читать.
3. `ci-poller` вернул ошибку (≤20 строк) → исправить точечно (лучше через `code-implementer`) → новый коммит → шаг 1.
4. Зелёная сборка → краткий отчёт по-русски со ссылкой на релиз/артефакт.

## Счётчик и сброс контекста
Считай сборки в сессии. После 3-й итерации (или при контексте > 150k): записать в `HANDOFF.md`
sha, статус CI, что осталось, и предложить продолжить в новой сессии. Не запускать четвёртую.

## Git
- Нельзя `rebase` поверх merge-коммитов апстрим-форка (Telegram и т.п.): только обычный commit + push, конфликты решать merge.
- Не force-push. Ветка — рабочая, не слитая в default без просьбы.

## Магазины приложений (проверка до отчёта)
Для вариантов под RuStore в манифесте собранного APK (`aapt2 dump permissions <apk>`) не должно быть:
`INSTALL_SHORTCUT`, `UNINSTALL_SHORTCUT`, `REQUEST_INSTALL_PACKAGES`. Есть — исправить манифест/флейвор, пересобрать (это итерация). Проверить наличие ABI `armeabi-v7a` и `arm64-v8a` и `versionCode`.

## Отчёт (≤6 строк)
Сделано / Проверка (run, статус) / Артефакт (ссылка) / Следующий шаг.
